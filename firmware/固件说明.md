## 1. 总览

**架构**：`上位机 --BLE--> ESP32-S3 --UART--> STM32`。ESP32 只做透传，不跑策略；PPO 推理和 50Hz 控制环全在 STM32 本地。上位机断连，猫照样站得住、走得动，只是收不到新指令。

**核心原则**：「停止」≠「卸力」。失联/急停 = 保持出力站住；唯一卸力 = 安全故障（§12）或策略更新中，由主循环每拍广播 `0x28=0`。云台与一切状态解耦，永不主动回中。

**模块清单**（自下而上分层，新函数插对应区块）：

| 模块 | 职责 | 状态 |
|---|---|---|
| cat_sys | 时钟 168MHz / 毫秒时基 / 观测区（CCM） | 【实测】 |
| cat_servo | STS3215 驱动（13 API + 51 地址 + 12 指令码 + 8 错误码） | 【实测】12 颗全绿 |
| cat_imu | YbImu 驱动，100Hz 主动上报 | 【实测】98.5~100Hz |
| cat_esp32 | 上位机链路（USART3）：收发/解析/0xCC 变长帧通道 | 【实测】 |

**启动流程**：时钟 → 时基 → 观测区清零 → IWDG → 查 KEY0（按住=更新模式，只开 ESP32 链路）→ 正常模式：舵机/IMU/ESP32/云台/观测 初始化 → 等外设就绪（10s 窗口）→ 补设 IMU 100Hz → 选策略（扫双槽）→ 主循环 50Hz。

主循环每拍：解析上位机指令 → IMU → 舵机同步读（12 颗 15B）→ 安全保护 → 观测更新 → 动作播放或策略推理 → 写舵机 → 故障卸力广播 → 上报（10Hz 分 5 片）。拍尾喂狗后 `__WFI()` 睡眠等下一拍。

## 3. 时钟与系统层（cat_sys）

**必须先配时钟**。STM32 复位后跑 HSI 16MHz，不配 PLL 所有波特率差 10 倍，舵机和 IMU 一个都连不上，现象像"接线坏了"【实测 2026-09-25】。排查：读 `RCC->CFGR` 的 SWS 位。

配置四步：开 HSE（起不来走 HSI 退路）→ Flash 5WS + 预取/缓存 → PLL 1MHz 进 ×336÷2 → 切 PLL + 总线分频。5WS 依据数据手册 2.7~3.6V 档 30MHz 上限【手册】；ART 加速器让取指等效 0 等待，不用搬 RAM【手册】。

**观测区**（`dbg_t g_dbg`，固定放 CCM `0x10000000`）是给 ST-Link 直读的调试窗口：
- 放 CCM 是因为 ARMCC `at()` 会"从 RAM 起点填充到指定地址"——放 SRAM 末尾实测 ZI 涨到 124KB，放 CCM 起点填充为 0【实测】。
- 掉电不清零，main 开头必须 `memset`（否则读到上次运行残留）。
- 两个保险：魔数 `0xCA7DB001` 判地址对错；`sizeof(dbg_t)==464` 编译期断言，改结构体忘同步读法会直接编译报错。
- 读法：`STM32_Programmer_CLI.exe -c port=SWD mode=hotplug -r32 0x10000000 464`（工具 `tools/read_dbg.py`）。

**时基**：SysTick 1ms，`LOAD = 168000-1`（递减到 0，off-by-one）。优先级压到 15（最低）——优先级高会插队通信中断拖慢串口响应，把 IMU 帧率打乱【实测 2026-09-27】。`g_ms` 必须 `volatile`（中断改、主循环读）。

**超时比较用差值**：`sys_elapsed()` 内部 `(g_ms - from) >= span`，无符号减法天然回绕安全（49.7 天溢出一次）。别写 `g_ms >= from + span`。

**睡眠节拍**：拍尾 `__WFI()`。睡眠只停内核时钟，SysTick 和外设照常跑，每 1ms 唤醒一次看是否到点【手册 RM0090】。喂狗在睡之前，睡死有 IWDG 兜底。

## 4. 通信（cat_esp32）

三条链路都靠**中断收字节进环形缓冲、主循环解析**：中断停留最短，不跟 50Hz 抢时间。缓冲满时**丢最旧不丢新**——丢新会导致永远吃旧数据且静默不报错；丢旧只丢一帧，状态机靠帧头重新同步。

| | 生产频率 | 缓冲 | 帧 |
|---|---|---|---|
| IMU | 100Hz 持续推 | 256B | 17~21B |
| 上位机 | 上位机发才有 | 256B（OTA 兜底加大） | 10B 控制帧 / 0xCC 变长帧 |

**下行控制帧**（10B 固定）：`AA 55 | vx[2] | wz[2] | flags[1] | pan | tilt | ck`，vx/wz 为 int16/1000，flags 只有 bit0=使能，ck 不含帧头。帧格式改必须两端同步改校验范围——曾出现 12B 对 10B 错位但校验照样过、静默解析全错【实测 2026-09-27】。

**DEADMAN**：1000ms 没收到有效帧 → 使能/vx/wz 归零（云台保持）。取值 > 发送间隔×5，具体对 BLE 抖动的余量未实测校准【存疑】。

**0xCC 变长帧通道**：`CC | len | 载荷 | ck`，len≤96，载荷首字节=子类型。策略 OTA（0x70~0x74）与动作加载（0x10/0x20/0x30）共用此通道，由 main 编排层分派。OTA 帧不刷新 DEADMAN（更新态本已卸力）。上行应答统一走 `5A A5 | len | type | 载荷 | ck` 帧（`esp32_send_up`），type：0x76 策略 ACK / 0x77 策略 STAT / 0x78 动作 ACK。

已知取舍：环形缓冲 `rx_r` 被中断（满时丢最旧）和主循环同时写，极端时序可能丢/重 1 字节，靠帧校验兜底丢整帧【推演，后果限于偶发丢帧】。

## 5. 舵机驱动（cat_servo）

协议帧：`FF FF | ID | LEN | 指令/ERROR | 数据… | CK`，CK = 从 ID 起取反累加，不含字头。LEN = 数据个数 + 2。指令码 12 条、内存表 51 项均已与手册脚本逐条比对【实测】。

**关键参数**：
- `BUFFER=128`：最长帧 = 12 颗 SyncWrite 6B/颗 = 92B。原来是 64，发不出"位置+时间+速度"【实测】。
- `SCS_TMO_US=5000`：依据第一版实测"12 颗读全反馈 3.3ms"，5ms 留 1.5 倍余量【实测】。
- `SCS_SYNC_GROUP=4`：12 颗一帧读（276B 长突发）必丢尾 1~2 字节（CH343 驱动板坑），≤4 颗/组 9/9 全中【实测】。写单向不分组。
- 同步读按 ID 认领帧，不按"第 k 帧 = 第 k 颗"——某颗掉线时后续帧整体前移。
- 同步写必须一条帧写完 12 颗，否则分批先后动，毁掉同步意义。上限 9B/颗。

**观测块**：一条 SyncRead 从 `0x38` 读 15B，一次拿全位置/速度/负载/电压/温度/状态/移动/电流：偏移 0~1 位置、2~3 速度（i16）、4~5 负载、6 电压、7 温度、9 状态位、13~14 电流（i16，**有符号，必须用 `scs_i16()`**）。12 颗共 180B。

**多字节量**全部低字节在前。速度/电流是有符号量。位置单位 0.087°/步（4096=12bit，编码器在输出轴，不除减速比）【实测与手册一致】。

**已实现的单颗指令**：`servo_reset`（0x0A 清圈数）、`servo_recovery`（0x06 恢复出厂，**抹掉全部 EPROM 配置，不可撤销**，用前先 0x09 备份）。0x04/0x05（异步写）不做：我们 12 颗同地址同长度，SyncWrite 一条 0.9ms 完胜。

**改 EPROM 参数**（以电压上限为例）：先写 `0x37=0` 解锁 → 写目标地址 → 写 `0x37=1` 上锁 → **等 50ms** → 读回验证。等 50ms 是踩出来的：写完立刻读会读到旧值误判失败。判据用 `!= SCS_ERR_TIMEOUT` 而非 `== SCS_OK`（带错误位应答时后者为假）。本车 12 颗已把过压阈值 0x0E 从 80(8.0V) 改到 90(9.0V)（2S 锂电满电 8.4V），永久生效【实测 2026-09-25】。换新舵机要重跑一次。

**0x43 地址存疑**【存疑】：手册 txt 写"目标位置(只读)"，xlsx 写"无定义"，两表只此一处冲突。第一版解析且用过一处，但从未有打印验证过它的值。当前处置：不定义、不调用。裁决法：写 0x2A 已知值再读 0x43 对比。即使存在也只是 0x2A 的镜像，无用。

**DWT 依赖**：收超时和耗时探针都靠 `DWT->CYCCNT`，而烧录/调试工具连接时会按自己的配置重写 `DEMCR`（=0），把秒表清掉。症状：观测区魔数正常但 6 个耗时探针全 0，且舵机不应答时 `servo_data_recv` 永不超时 → 死循环卡死。**规避：烧录/进调试会话后按一次复位**（固件重跑 `servo_init` 重开）【实测 2026-09-27】。验证：`-r32 0xE000EDFC 4` 应回 `0x01000000`。

其他手册坑：例 4"用非广播 ID 0xFE"是笔误（0xFE 就是广播）；1.1 与 1.3.1 对"广播 PING"说法矛盾（别用，多颗会撞答）；烧录必须加 `-hardRst`。

## 6. IMU（cat_imu）

亚博 YbImu，USART2 115200，**主动上报**（不问也推）。出厂 25Hz，上电发 `0x60 {100, 0x5F}` 设 100Hz。

**输出频率不保存**：每次上电 `imu_init` 里那条设置指令会丢，靠 `imu_ensure_rate()` 在确认模块出帧后实测帧率、不够就补发【实测 2026-09-25，观测区 `imu_rate_fix=1`】。必须在 `boot_wait_ready()` 之后调，放 init 里会丢（模块没醒）。

**帧率 = 3 × 输出频率**（每周期推 0x04 原始 / 0x16 四元数 / 0x26 欧拉角三类）。实测 300.0 帧/s ÷ 3 = 100.0Hz【实测 2026-09-27】。

**解析状态机**要点：等包头 2（`0x23`）那步，如果来的还是 `0x7E` 要保持等而非复位——否则"0x7E 噪声 + 0x7E 0x23 真帧头"场景会吃掉真帧头白丢一帧【实测】。"等包头 2"直接复位是官方驱动的坑之一（另两个：中断里死等 RXNE、攒够 127B 才推缓冲），均已改掉。

**重力方向** `imu_get_grav()` = 世界 -Z 在机体系的单位向量（观测 obs[6:9)）：`[2(wy−xz), −2(yz+wx), −(1−2(x²+y²))]`。真机实测静止时 `[-0.005, -0.121, -0.993]`，模长精确到小数 4 位，与欧拉角互洽【实测 2026-09-25】。注意与第一版公式互为共轭（约定差异），本版与训练侧对齐。

**没收到帧时的假象**：四元数初值全 0，代入公式得 `[0,0,-1]`，看起来正立其实没数据。采信任何 IMU 数据前先看 `imu_get_frames()` 在不在涨。主循环另有 IMU 静默检测：连续 500ms（25 拍）无新帧 → 停发新目标（保持出力，不卸力），探针 `g_dbg.imu_silent`。

**模块安装轴向未与机身核对**【存疑】：静止时加速度计向量应 ≈ −gravity，可自校验；若不符需加一次性旋转修正。

**`g_frames` 是 uint16_t**，300 帧/s 下 218 秒回绕。只能两次读差值判断"有没有新帧"，不能当累计帧数算频率（read_dbg 已内置差值法）。

## 7. 观测组装（cat_obs）

59 维 = linvel(3) + gyro(3) + gravity(3) + cmd(2) + jpos(12) + jvel(12) + tau(12) + last_act(12)。八段正好铺满。

**维度三重依据**【实测】：① 部署策略 npz 的 W1=(59,512)；② 第一版固件 `#define OBS_DIM 59`；③ 训练侧 `joystick.py` 拼装表达式 3+3+3+2+12+12+12+12=59。注意训练代码里有行残留注释写 60——**信表达式别信注释**。对齐目标是"要部署的那个策略文件"，不是训练代码。

**cmd 钳位 ±0.5**：训练采样范围 vx/wz 均 ±0.5（`joystick.py:163`）。协议允许 ±32.7，不钳的话策略见到训练时没见过的输入，行为不可预测且静默不报错。钳在 `obs_set_cmd()` 入口，不在解析层。与训练侧采样范围耦合，那边改了这里要跟。

**tau 换算**：`tau = 电流LSB × 6.5mA × 0.784 N·m/A`。Kt=0.784 与训练侧同款（其 tau_bias 注释 `45mA×0.784≈0.035` 可对账）。**不加训练侧的 tau_bias**——那是仿真补真机基线用的，真机偏差天然在读数里，再加是重复计入。

**jvel 是固件近似**【推演，固有 sim2real 差异】：训练侧用仿真真值 `data.qvel`；真机只能位置差分 + 一阶低通（fc=25Hz，τ=0.006366，系数 alpha=dt/(dt+τ)）。低通把差分噪声压到接近仿真量级，**τ 待实测调**。dt 用 DWT 实测拍长（拍拉长时不失真）。

**计数↔弧度**：`rad = (counts − ZERO) × (2π/4096) × DIR`；逆变换 `obs_rad_to_counts()` 公用（策略动作与动作模块共用一份公式）。DIR 全 +1（2026-09-05 定稿，URDF 镜像 quat 已处理左右腿差异；第一版"前后分 ±"是错的）。

**标定表** `CAL_SERVO_ZERO` = {1852, 2640, 1433, 2177, 1551, 2592, 2078, 2364, 1414, 2110, 1400, 2889}（2026-09-10 复标定，0x38 连读三次取一致）。副作用：关节角 0 = 标定当天摆放姿态，手工误差表现为 FK 绝对角常数偏置——**差分速度会消掉它，不影响 linvel**。

**动作映射（翻身版，2026-09-28 起）**：`q = clip(act × scale, lo, hi)`，scale = max(|lo|,|hi|)。动作 = 绝对目标角。与训练侧 `joystick.py`/`Cat33Flip`/BC 标签完全同构。**口径是策略语义的一部分**：旧口径权重（v31/u4w/long1）在新固件上不可部署，必须配翻身版口径权重（b1 精修线）。限位表（rad）：

| 关节 | lo | hi | 关节 | lo | hi |
|---|---|---|---|---|---|
| RR abd/hip/knee | −1.30/−1.20/−0.14 | 0.70/0.52/3.00 | FR abd/hip/knee | −0.55/−1.20/−0.14 | 0.55/0.50/3.00 |
| RL abd/hip/knee | −0.70/−0.52/−3.00 | 1.30/1.20/0.14 | FL abd/hip/knee | −0.55/−0.50/−3.00 | 0.55/1.20/0.14 |

腿序：0-2 右后 / 3-5 左后 / 6-8 前右 / 9-11 前左，每腿 abd/hip/knee。表与模型 jnt_range 用 `tools/check_act_lim.py` 一条命令复核。改模型行程必须同步改固件表 + 重跑 `tools/gen_safety_limits.py`。

**跨模块约定**：`obs_set_lastact()` 灌的是上一拍输出（灌早了 = 未来信息泄漏）；`obs_update()` 的 counts 必须是同一拍的一组；cat_obs include imu/vel_est 是"聚合层"对"模块间不横向 include"铁律的刻意例外（第一版同款）。

## 8. 速度估计（cat_vel_est）

输出机体系线速度（观测 obs[0:3)）。原理：支撑腿足端世界静止 ⟹ 足端机体系位置变化率 = −机体速度。每腿报一个 v_i，分量中位数做初值（抑制单腿异常），再按与上拍估计的残差做高斯软权重加权（摆动腿残差大自动降权），抬腿粗筛剔除。垂直分量单靠腿估不出，恒 0。

几何来自 cat3.4 模型 + SolidWorks 实测：3 级链（髋侧摆→髋俯仰→生理膝）+ FOOT_OFF 偏移表 + 四连杆多项式（曲柄角→生理膝角，4 阶）。与 Python 原型 `odometry_geo.py` 逐字节一致，勿单方面改。**换腿型必须重核三张表**。

精度：FK 三独立参照物验证（初始态 <1mm / 站姿对比 1.21mm / 高度闭环 0.44mm）；整体误差 0.073 m/s【实测 SIL】。2026-09-05 重写判据（原实现把 |pdot| 当足端世界速度，牵连速度 0.5m/s 量级会把权重全灭）。

SIL 诊断输出（CAT_SIL_DIAG 下的 stderr 对拍）未移植到本版【存疑/待办】，做 SIL 时回第一版取。

## 9. 策略前向（cat_policy）

网络：`59 → 512 → 256 → 128 → 24`，前三层 swish，头层取前 12 维过 tanh 当动作。int8 权重 + 按输出通道 float scale：`out[o] = (Σ in[i]·W[i][o])·ws[o] + b[o]`。权重 (in,out) 行主序；输入是归一化 float 不能取整；bias 不乘 ws。权重由 `tools/npz_to_c.py` 从 npz 生成，`POL_BUILD_ID` = npz 的 md5 前 12 位。

**`cat_policy.c` 必须单独 -O3**（工程其余 -O0）【实测 2026-09-27】：-O0 下单层 26.3ms 吃整拍 84%；-O3 + 8 分块 + uint32 循环变量 → **12.78ms/次（4.375 条/MAC）**，整拍 20.0ms。瓶颈是 M4F 无 int8 SIMD，每个权重 LDRSB+VMOV+VCVT+VMLA 4 条省不掉；16 分块会挤爆 FPU 寄存器。再快只有蒸馏小网络或 CMSIS-NN int8（后者须与训练侧 int8 参考对拍）。**别调回 -O0，Keil GUI 改选项时注意别覆盖 per-file 设置。**

**权重来源（双槽指针化，2026-09-29）**：`policy_select()` 开机扫槽 A/B（各 256KB：头部 72B + 数据 blob），全验（magic/维度/pose_hash/全量 CRC32）取有效且 seq 大者；指针切到槽数据，`policy_run()` 只读指针。当前 `CAT_POL_FACTORY=0`（无出厂，policy_weights.c 移出 Keil 工程省 ~205KB；两槽空 = 无策略待机）。SIL 构建用 `-DCAT_POL_FACTORY=1` + 自带权重，宏被 `#ifndef` 包住才能被 `-D` 覆盖。槽格式与流程见协议第七章。

**与训练侧对拍**：`tools/check_policy_err.py` 从观测区重建 obs 与 npz 同网络对比，最大绝对差 0.00012（相对满量程 0.014%）【实测 2026-09-27】。判断标准看 1e-4 量级，不是某个具体数字。

**DWT 秒表**：耗时探针依赖 CYCCNT，被调试工具清掉的问题见 §5（复位解决）。

## 10. 策略在线更新（cat_polupd）

双槽 Flash OTA，**永不砖**：只擦"非激活槽"，magic 最后写（唯一有效开关），END 后 read-back 全量 CRC 复检，失败擦头部定无效。激活槽在物理上永不被写。协议第七章。

- 槽 A = `0x080C0000`（S10+S11），槽 B = `0x08080000`（S8+S9），各 256KB。
- 头部 72B：magic/fmt/seq/data_len/data_crc/obs_dim/act_dim/pose_hash/hdr_crc/tag[24]/build[12]。
- seq 必须大于激活槽（防误刷旧版）；pose_hash 校验"策略与姿态表同源"（改模型即拒收旧包）。
- 时序：逐帧等 ACK 停等；DATA 每帧 ≤64B、按偏移顺序；擦 2 扇区实测 >8s。
- **IWDG 配合**：擦除前 `safety_iwdg_relax()` 放宽到 32s（RLR=4000 @125Hz），扇区间喂狗，完事 restore。RLR 只有 12 位（≤4095），拉长超时必须改预分频不能加 RLR——写 15000 会被截成 2712 反而更短【实测 2026-09-30】。
- **更新模式（2026-09-30 定）**：按住 KEY0 上电进入，只初始化 ESP32 链路（IMU/舵机/云台不初始化）。起因：正常模式擦 Flash 期间 IMU 的 100Hz 数据流积压，擦完形成中断风暴把主循环饿死（pyocd 抓现场实锤）。正常模式收 BEGIN 一律回 0x1A 拒。
- END 成功后 main 立即 `policy_select()` 重选，指针切新槽即生效，无需复位（OTA 模式除外，那里软复位重启）。
- STAT 应答用槽有效性缓存（`s_slot_ok`，由 scan 维护、BEGIN 擦槽后清 0），避免每次查询做双槽全量 CRC 阻塞主循环 ~40ms。

## 11. 动作加载与播放（cat_action）

下发一串关键帧动作（翻身/打招呼等）。PC 读 CSV → 打包 0xCC 帧 → 固件存 RAM 表（64 帧 × 64B）→ 播放。**固件不解析 CSV 文本**，字段重排（CSV 是 `seg,hold,j0..j11,…`，帧是 `j0..j11,seg,hold,…`，全 float32）由 PC 做。协议第八章。

**CSV 字段**：必需 14 列 `seg_s,hold_s,j0..j11`；可选 `torque,speed,acc`（缺省 1000/0/0）。seg∈[0.05,25]、hold∈[0,25]、关节角超限**钳位不拒帧**、含 NaN 拒帧、同文件列数必须一致、≤64 行。编码 UTF-8（容忍 BOM/CRLF），`#` 注释/空行/表头由 PC 跳过。

**播放**：三段式——进场 0.8s（当前角→首帧，每拍从当前位置逼近的指数过渡）→ 逐帧 smoothstep 插值 + 保持 → 出场 0.8s 回默认站姿。全程 5 rad/s 限速 + 关节限位截断。每帧 torque/acc 参数变了才写寄存器（0x30/0x29），speed 搭位置 6B 连续写的车（0x2A 位置 + 0x2C 时间 + 0x2E 速度）。出场/中断后参数回默认档，防后续策略被限流档卡住。

**门卫**：BEGIN 与 END 都要求「未使能 + 无故障」——站着不动才能换表。动作表只写 RAM（全程 ~40ms），**不需要 KEY0 更新模式**（那是为擦 Flash 设的）。END 即请求播放；主循环门控受理，门卫不过请求丢弃不挂起。播放中只要求无故障——中途按停止/失联不打断（动作是本地序列，停半路更糟）；故障 → abort 跳到出场段平滑回站姿（不是硬停）。

**当前状态**：编译通过（Code 20862 内含），**未上机**【存疑】。观测区探针：`act_frames`（表帧数）/ `act_stage`（0 空闲/1 进场/2 关键帧/3 出场）/ `act_idx`。

## 12. 安全（cat_safety）

### 12.1 目标钳位

策略/动作输出 → 计数后的最后一道闸：逐颗夹进机械行程表（`SAFETY_GOAL_MIN/MAX`），只夹不拒，返回被夹颗数（观测区 `safety_clip`，平时 0）。表由 `tools/gen_safety_limits.py` 从模型 joint range + CAL_SERVO_ZERO 生成（向内取整）。**重标定或改行程后必须重跑脚本更新表**，再用 `check_act_lim.py` 对拍。与 `CAT_POSE_LIM_*` 的关系：LIM 是动作映射的方盒（rad），钳位表是上总线的最后防线（counts，更保守）。

### 12.2 反馈保护（safety_protect_poll）

每拍拿 12 颗的电压/温度/电流，任一命中 → 锁存故障（不自动恢复，只能复位清），由 main 每拍广播 `0x28=0` 卸力。只在同步读齐全的拍里调用。

| 项 | 阈值 | 去抖 |
|---|---|---|
| 电压 | 单颗 < 6.3V（63 LSB，0.1V/LSB） | 连续 3 拍确认 |
| 电流 | 单颗 \|i\| ≥ 2.0A（308 LSB ≈ 堵转 80%）且 100 拍滚动窗内占比 ≥80% | 滚动窗（防跨窗口漏判） |
| 温度 | 单颗 ≥ 70℃ | 连续 3 拍确认 |

**去抖依据**【实测 2026-09-30】：ID2 温度寄存器偶发单拍假读数 70℃（其余颗 26~29℃，下拍恢复），单拍即锁存导致"偶发趴下"，当天活捉复现。改连续 3 拍确认（干净一拍清零），真过热只延迟 60ms。温/压计数逐颗独立（防多颗轮流假读凑数）。故障码取首因（电流先触发不被同拍温度覆盖）。电流滚动窗 1.2KB RAM。

### 12.3 IWDG 看门狗

独立 LSI 时钟域（≈32kHz）的硬件倒计时：主循环每拍喂一次（20ms），卡死超 1s 自动复位。参数：PR=6（÷256→125Hz）、RLR=125（1s）；OTA 擦除期间 relax 到 RLR=4000（32s），**RLR 只有 12 位**，拉长必须动预分频【实测踩坑见 §10】。调试冻结已开（DBGMCU，挂调试器 halt 时 IWDG 暂停，断点单步不会误复位）。开关 `CAT_IWDG_ENABLE`。

**复位源**：`reset_cause` 0=上电 1=IWDG 2=软复位（OTA 后）3=HardFault 被救（异常 Handler 在 CCM 留痕 `fault_mark=0xFA017001`，复位后 main 读取细化，只在 IWDG 复位时采信，冷启动不误报）。

**安全闸**（main）：发指令/开扭矩 = `无故障 && 在连 && 使能 && IMU 有数据`；卸力优先于一切。停≠卸力。
