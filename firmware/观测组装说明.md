# 观测组装说明（cat_obs.c / cat_obs.h）

> 代码里只留「做什么 + 关键约束」，为什么这么做、依据从哪来，记在这里。
> 上游依据：`通信协议.txt`（链路）、训练侧 `joystick.py` / `leg_odometry.py`（WSL）。

---

## 一、为什么是 59 维

**三条依据，逐条独立**（维度错一位整个策略就废，所以锁了三重）：

1. **实测策略文件**：`mujoco/play/cat33_policy_v31.npz` 的 `W1=(59,512)`、`obs_mean/obs_std` 均为 `(59,)`
2. **第一版固件**：`CAT_APP/cat_config.h` 的 `#define OBS_DIM 59`，注释写着
   "novy 2026-09-10: 删侧移(vy), 命令 3->2 维"
3. ⭐ **训练侧最新代码**（WSL，2026-09-16）：
   `state_obs = jp.concatenate([linvel, gyro, gravity, cmd, jpos, jvel, tau, last_act])`
   —— 3+3+3+**2**+12+12+12+12 = 59

⚠️ **它自己那行注释还写着 `# 60`**（同文件 516 行）—— 是改动后没更新的残留。
所以**别信注释，要看拼装表达式**。

⚠️ **对齐目标是「要部署的那个策略文件」，不是训练代码。** 训练代码改成 60 不代表部署的是 60。

## 三、命令范围 ±0.5（必须钳）

- **训练侧范围**（WSL `joystick.py:163`）：
  `command_config = create(a=[0.5, 0.5], b=[0.9, 0.5], zero_prob=0.1, fixed=None)`
  → vx 和 wz 都采样自 `±0.5`（原 3 维版是 `[0.5, 0.2, 0.5]`，vy 那维已删）
- **不钳会怎样**：上位机协议本身允许 `int16/1000 = ±32.7`，发个 2.0 进来，策略收到的是
  **训练时从没见过的输入** → 行为不可预测，**而且不会报任何错**
- **所以钳在 `obs_set_cmd()` 这个入口**（不是钳在解析层）—— 不管谁调、怎么调，进 obs 的一定合法

⚠️ 两边是**耦合**的：WSL 侧改了采样范围，这里要跟着改。

## 四、tau 的换算系数

```
tau[N·m] = 电流LSB × 6.5mA × 0.784 N·m/A
```

| 系数 | 值 | 出处 |
|---|---|---|
| 电流分辨率 | `6.5e-3` A/LSB | 舵机手册；`cat_servo.h` 的 `SCS_ADDR_PRESENT_CURR` 注释也写"6.5mA/LSB" |
| 扭矩常数 Kt | `0.784` N·m/A | ⭐ **训练侧同款** —— WSL `joystick.py:58` 的 tau_bias 注释：<br>`"电流基线(45mA×0.784≈0.035)"`，且 `45mA × 0.784 = 0.0353 N·m` 对得上 |

**⚠️ 不加训练侧的 `tau_bias`**：那是给**仿真**补真机基线偏差用的；
真机的偏差（0~45mA）**天然就在读数里**，再加就是重复计入。

**⚠️ `0x45` 是有符号量** → 必须用 `scs_i16()` 读，不能用 `scs_u16()`。

## 五、jvel：固件自研的近似（固有 sim2real 差异）

| | 来源 |
|---|---|
| 训练侧 | `data.qvel` —— **仿真真值**，既没差分也没滤波 |
| 固件 | 位置差分 + 一阶低通（`fc = 25Hz`，`τ = 1/(2π·25) = 0.006366`），`alpha = dt/(dt+τ)` |

**这个差异消不掉** —— 真机没有关节速度传感器，只能估。低通的作用是把差分噪声压到接近仿真的量级。
**系数待实测调**（第一版注释也标着"待实测调"）。

## 六、计数 → 弧度

```
弧度/步 = 2π/4096 ≈ 0.001534    (即 0.0879°/步)
```

- 4096 = 12bit 磁编码
- ⚠️ **STS3215 的编码器在输出轴上**，所以 4096 步就是整圈**输出**角，**不用再除减速比**
  （第一版留过一句"若输出轴前有减速需除减速比"—— 不适用，特此澄清）

---

## 七、标定表

### `CAL_SERVO_ZERO[12]` —— 关节角 0 对应的舵机计数
```
1852, 2640, 1433, 2177, 1551, 2592, 2078, 2364, 1414, 2110, 1400, 2889
```
- 2026-09-10 复标定，只读 `0x38` 连读三次取一致值（仅 ID5 抖 1 count = 0.09°）
- **副作用**："关节角 0"的物理姿态 = 标定当天的摆放姿态。手工摆放误差（±几度）
  表现为 FK 绝对角的**常数偏置** —— 差分速度估计会消掉它，**不影响 linvel**

### `CAL_SERVO_DIR[12]` —— 全 +1
- 2026-09-05 定稿。依据：URDF 设计保证"编码增大 = 模型正方向"（右手定则 +z；
  左右腿限位精确镜像也印证了）
- ⚠️ **第一版曾按"前后分"填 `{+1×6, -1×6}`，那是错的** —— 会导致前后腿镜像颠倒。
  模型的镜像 quat 本身已负责处理左右腿物理差异，这里再翻就翻了两次

### 观测序号 → 总线 ID
恒等加一（序号 `i` ↔ ID `i+1`）。第一版有张 `CAL_SERVO_ID` 表存这个，第二版没收 ——
写死成 `OBS_SID_OF()` 表达式更不容易改错。

### 腿的顺序
`0-2 右后 / 3-5 左后 / 6-8 前右 / 9-11 前左`，每条腿 `abd / hip / knee`。
与 `cat_vel_est.c` 的 `CH[]`、`mujoco` 模型的 joint 顺序一致。

## 八、为什么 include 了 imu 和里程计

`cat_obs.c` include 了 `cat_imu.h` 和 `cat_vel_est.h`，
这是铁律⑦「模块之间不许横向 include」的**例外**：

- 理由：`cat_obs` 的职责**本身就是**"聚合各来源的数据"（第一版也是这么写的）
- 想严格化的话：imu / 里程计都加 `obs_set_xxx()` 灌数接口，由 `main.c` 逐项喂进去，
  obs 就彻底不认识别的模块 —— 代价是 `main.c` 变长
- **当前选择：保留例外**（待煜辰最终裁决）

## 九、跨模块的小约定

- `obs_set_lastact()` 灌的是**【上一拍】**的输出，不是这一拍 ——
  编排层要在策略跑完、动作发出去**之后**才回调它，否则策略会看到"这一拍的自己"（**未来信息泄漏**）
- `obs_update()` 传进来的 `bus_counts[]` 必须是**同一时刻**读到的那一组（别混拍）
- 上电初值：`jpos = 默认站姿`（所以 jpos 段输出 0）、其余全 0 —— 与训练侧第一拍一致

## 十、动作 → 关节角映射（翻身版，2026-09-28 切换）

```
q[rad] = clip(act × scale, lo, hi)          scale = max(|lo|, |hi|)
计数    = CAL_SERVO_ZERO + q × CAL_SERVO_DIR / (2π/4096)
```

- **语义**：动作 = **绝对目标角**（"逐关节按物理限位，不多不少"），不再是"默认站姿 + 偏移"。
- **旧口径已废弃**：`q = 默认站姿 + act×0.75`（旧 `ACTION_SCALE`，v31 时代的部署约定）。
- **为什么要切**：固件恢复动作 **37.7% 帧越出旧 ±0.75 盒**（12 通道中 8 个越界；且"裁剪回放"对照
  noclip 83/86 vs clip 0/86 → 旧盒盖不住恢复）——翻身/恢复需要全行程；翻身版一步盖全行程，
  且与训练侧 `joystick.py`（2026-09-28 起）、`Cat33Flip`、BC 数据标签（`act = q_tgt/scale`）**完全同构**。
- **限位表来源**：模型 `cat3.4/scene_full.xml` 的 `jnt_range[ACTIVE_JOINTS]`（实测读取）；
  与 `OBS_DEFAULT_POSE` 同源互校（脚本逐条比对，ALL MATCH）。
- ⚠️ **两边耦合**：改模型关节范围 → 必须同时改固件表 + 训练侧（`joystick.py` 自动读，固件是手抄）。
- ⚠️ **口径 = 策略语义的一部分**：旧口径训练出的权重（v31/u4w/long1 等）**在新固件上不可直接部署**；
  配套的必须是翻身版口径训练的权重（b1 精修线 / 翻身版重导）。SIL 与此同源（build_host2 直接编 `cat_obs.c`）。
- 新口径下 q 被限位包住 → `obs_act_to_counts` 的 counts 钳位 [0,4095] 只剩**防御意义**
  （实测各关节极限位置 counts 全部落在 [636, 3389]，天然安全；返回值 `pol_clip` 正常恒 0）。
