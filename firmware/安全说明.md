## ① 目标钳位（safety_clamp_counts）

### 它解决什么问题
策略输出经 `obs_act_to_counts()` 换算成 12 颗舵机的**目标计数**后、上总线之前的最后一道闸：
把每颗目标逐颗夹进 `[SAFETY_GOAL_MIN, SAFETY_GOAL_MAX]`（机械行程的计数版），
防"策略/异常值把某颗指挥到行程之外"。语义 = **逐颗夹住、不拒发**，返回被钳颗数 ——
与第一版"整拍拒发"不同（单颗异常不该冻结整拍）。

### 链条里的位置（main.c 2.3 段）
`obs_act_to_counts() → safety_clamp_counts() → servo_sync_write()`
被钳颗数 → 观测区 `safety_clip`（频率指标：平时 0；"策略顶机械限位"时 >0 —— 2026-09-30 真机出现过 1）。

### 表怎么来的（`tools/gen_safety_limits.py`，单一数据源）
- 数据源：① `robot.xml` 的 `<joint range>`（cat3.4 机械行程；**用 XML 解析器读**——
  正则会吃到行内 `actuatorfrcrange`，踩过）② `cat_obs.c` 的 `CAL_SERVO_ZERO`（唯一真源）
- 换算：`counts = ZERO + q / R2R`（R2R = 6.2832/4096，与 `obs_act_to_counts` 同一公式；DIR 全 +1）
- 取整：**向内取整**（下限向上 ceil / 上限向下 floor）—— 保证钳位结果不越模型行程
- 输出：按观测序（后右 | 后左 | 前右 | 前左）可直接粘贴的两个数组

### ⚠️ 重标定 / 改行程后的流程（必须）
1. 改 `CAL_SERVO_ZERO`（重标定）或改模型 `<joint range>`
2. 重跑 `python tools/gen_safety_limits.py`
3. 按其输出更新 `cat_safety.c` 的两个表
4. 跑 `tools/check_act_lim.py` 逐条对拍（钳位表 ↔ 模型行程 ↔ obs 换算；允许 ≤1 count 取整差）
5. 编译（看 Code / RO-data 变动）

### 边界
- 只钳"位置"：不拒发、不限速；"连续大量越界 → 故障"留给以后，别塞进来。
- 与 `cat_pose.c` 的 `CAT_POSE_LIM_*` 同源不同用：LIM 是"动作方盒"（rad，翻身版映射用）；
  钳位表是"上总线的最后防线"（counts，向内取整更保守）。

## ② 反馈保护（safety_protect_poll）

### 它解决什么问题
每拍拿 12 颗舵机的 电压 / 温度 / 电流 反馈，任一命中阈值 → **锁存故障**（`safety_trip_t`），
由编排层（main.c 2.5 段）**每拍广播 `0x28=0` 卸力**。⚠️ 锁存后**不自动恢复** —— 重上电 / 按复位才清。

### 触发条件（阈值 2026-09-28 煜辰定；单位换算）
| 项 | 阈值 | 换算 | 备注 |
|---|---|---|---|
| 电压 | 单颗 < 6.3V（63 LSB） | 0x3E，0.1V/LSB | 连续 3 拍确认（09-30 去抖） |
| 电流 | 单颗 \|电流\| ≥ 2.0A（308 LSB ≈ 堵转 80%）且在**滚动 2s 窗口**内过载占比 ≥80% | 0x45，6.5mA/LSB | 有符号量（scs_i16） |
| 温度 | 单颗 ≥ 70℃ | 0x3F，℃ | 连续 3 拍确认（09-30 去抖） |

### 电流为什么必须"滚动窗口"（推演）
"每 100 拍清零重数"的写法会漏判：恰好跨窗口边界的 2 秒满过载（如 50+50 拍）两段都到不了 80 →
一次都不触发；随机起点约六成会漏。⇒ 改为 **100 拍环形滚动**（每拍换出最老一拍、记入本拍、查滚动和）。
连续满过载 80 拍（1.6s）先行触发（安全方向）；81% 占空稳态 ≈ 2s 触发。RAM 12×100B = 1.2KB。

### 去抖（2026-09-30 加，仅温/压）—— 真机实锤
调试实录：**ID2 温度寄存器偶发单拍假读数 70℃**（其余 11 颗 26~29℃、下一拍即恢复），
旧逻辑"单拍 ≥70 即锁存" → 直接卸力趴下（"偶发趴下"两次的原因，当天活捉复现）。
修复：电压/温度改 **连续 3 拍确认**才锁存（任一干净拍即清零重数）—— 单拍毛刺被滤掉；
真过热是持续读数、只延迟 60ms 确认，安全方向无损。电流滚动窗逻辑不变。
（旁证：总线读数偶发单拍毛刺是常态 —— ID6 也闪过 48℃ 单拍。）

### 调用契约（main 侧）
- 只在**同步读齐全（miss==0）**的拍里调；读数残缺的拍不喂，统计保持（不误清零 / 不误判）。
- 触发后 2.5 段**每拍重发**卸力广播（不依赖后续读数）；**优先于失联闸**（故障时连"保持出力"都不允许）。
- 使能闸：`safety_get_trip()==NONE && 在连 && enable` 才准发指令 / 开扭矩。
- `safety_get_trip()` 锁存值 → 观测区 `safety_trip`：`0`=正常 ｜ `1`=VOLT ｜ `2`=CURR ｜ `3`=TEMP

## ③ IWDG 看门狗

### 它解决什么问题

固件卡死（死循环、跑飞、某段 while 等不到应答）→ 主循环不再转 → 猫"僵住"且不会自愈，
只能人去拔电。IWDG 是 MCU 内部的独立倒计时器：**超过设定时间没人"喂狗"，硬件直接复位芯片**，
固件重启。相当于"没人拍它，它自己重启"。

注意它是**独立时钟域**的：时钟是 LSI（≈32kHz 的内部低速 RC），主时钟/PLL 即使挂了，
倒计时照样走 —— 这是普通定时器做不到的。

### 参数怎么算的

| 项 | 值 | 依据 |
|---|---|---|
| 时钟源 | LSI ≈ 32kHz | RM0090 IWDG 章；启动 IWDG 时 LSI 被强制打开（运行期间关不掉） |
| 预分频 | PR=6 → ÷256 → 125Hz | RM0090 预分频表 ⚠️ 不是 ÷64，理由见下 |
| 默认超时 | RLR=125 → **1s** | 125 计数 ÷ 125Hz = 1.0s |
| 放宽超时 | RLR=4000 → **32s** | 4000 ÷ 125 = 32.0s（OTA 擦除窗口） |

⚠️ **预分频为什么是 ÷256 而不是 ÷64（2026-09-30 真机踩坑）**：
RLR 只有 **12 位（≤4095）** —— ÷64（500Hz）下放宽上限只有 8.19s，而**实测本板
擦 2×128KB 扇区 >8s 擦不完**（生存测量实锤：固件在 BEGIN 后 ~8.0s 被 IWDG 打死）；
换 ÷256（125Hz）后 RLR=4000 就有 **32s** 余量。教训：想直接写 `RLR=15000` 拉长 ——
被硬件截断成 `2712`（=5.4s）反而更短，**拉长超时必须动预分频，不能只加 RLR**。
| 喂狗周期 | 主循环每拍 1 次 = 20ms | 富余 50 倍 |

超时值的选择：1s 要"大于任何一段正常的最长停摆"（主循环一拍 20ms、最长单步 servo_sync_read
约 2ms 级、OTA 写一包几 ms），同时"小于猫撞坏自己的时间尺度"。20ms vs 1s 差 50 倍，
抖动不会误触发。

### 两条写寄存器时的约束（都踩点过）

1. **KEYR 三条口令**：写 `0x5555` 才允许改 PR/RLR；写 `0xAAAA` = 喂狗；写 `0xCCCC` = 启动。
   启动后 LSI 被强制打开 —— 所以代码里**不手动开 LSI**（打开也关不掉，多此一举）。
2. **改 RLR 后要等 SR 的 RVU 位清零**（重载值同步到 LSI 域，要几个 LSI 周期）。
   ⚠️ 这个"等"**只在 IWDG 已经启动时才能做** —— 没启动 = LSI 没跑 = RVU 永远不会清 =
   死等卡死。所以 `safety_iwdg_relax/restore` 都用 `s_started` 把住门（见代码）。

### 调试冻结（DBGMCU）

`DBGMCU->APB1FZ |= DBG_IWDG_STOP`：挂调试器、命中断点让内核停住（halt）时，
**IWDG 暂停计数** —— 否则单步/断点一停超过 1s 就被复位，调试根本没法用。
只在"内核被调试器停住"时生效，正常运行时无影响。

### 复位源判定

`RCC->CSR` 的 `IWDGRSTF`（bit29）置位 = 本次复位是 IWDG 打的。开机读一次、
写进观测区 `g_dbg.reset_cause`（0=上电/复位键，1=IWDG），然后 `RMVF` 清全部复位标志
（不清的话下次读的还是"旧账"）。

用途：真机跑一晚，第二天读一眼就知道"它卡死自己复活过没有"。

### 和 OTA（策略在线更新）的配合

擦一个 128KB Flash 扇区要 1~4s，期间 CPU 取指全停 —— 正常跑的话必被 IWDG 误杀。
所以 cat_polupd 在擦/验前后调 `safety_iwdg_relax() / safety_iwdg_restore()`：
擦前放宽到 32s、擦完恢复 1s。（钩子位置在 cat_polupd.c 的 pol_iwdg_relax/restore。）

### 编译开关

`cat_config.h` 的 `CAT_IWDG_ENABLE`：1=上电启动（默认，别关）；0=不启动（纯开发模式备用闸）。
关掉时 `safety_iwdg_*` 全是空操作（`s_started=0` 把门），不会写寄存器。
