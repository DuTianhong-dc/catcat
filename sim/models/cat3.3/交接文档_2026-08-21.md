## 3. 关节与传动结构（必读，理解模型的关键）

### 关节层级（每条腿 5 个关节）

```
base_link (freejoint)
└─ LinkN      (hip 髋屈伸)  = joint1/6/11/16   ← 舵机驱动（大腿）
   └─ LinkN+1 (大腿/曲柄)   = joint2/7/12/17   ← 舵机驱动
      ├─ LinkN+2 (曲柄)     = joint3/8/13/18   ← 舵机驱动（真膝舵机）
      │  └─ LinkN+3 (连杆)  = joint4/9/14/19   ← 被动（四连杆中间杆）
      └─ LinkN+4 (小腿)     = joint5/10/15/20  ← 被动（四连杆输出）
```

**12 个舵机**：joint1/2/3、6/7/8（后腿），11/12/13、16/17/18（前腿），kp=100 kv=0.35（实测标定），forcerange ±1.91 N·m（STS3215 堵转 @7.4V）。

**8 个被动关节**：joint4/5、9/10、14/15、19/20（每腿 2 个），无 actuator，由四连杆闭环约束决定其位置。

### 腿配对

| 腿 | 关节 | 曲柄方向 | 对应 |
|----|------|---------|------|
| leg1 右后 | 1/2/3 + 被动 4/5 | +（0~170°） | joint3 → joint4/5 |
| leg2 左后 | 6/7/8 + 被动 9/10 | −（0~−170°） | joint8 → joint9/10 |
| leg3 右前 | 11/12/13 + 被动 14/15 | +（0~170°） | joint13 → joint14/15 |
| leg4 左前 | 16/17/18 + 被动 19/20 | −（0~−170°） | joint18 → joint19/20 |

**leg2/leg4 曲柄方向为负**（限位 [-3, 0.14] rad），与 leg1/3 是 y 镜像。

## 4. 两版本差异详解

### connect 版（旧，对照）

```xml
<equality>
  <connect name="leg1_fourbar" site1="leg1_link4_connect" site2="leg1_link5_connect"
      solref="0.003 1.05" solimp="1.0 0.95 0.002 1.0 6"/>
  <!-- 共 4 个，leg2/3/4 同理 -->
</equality>
```

- **原理**：`connect` 约束两个 site 距离为 0（四连杆缝合点）。MuJoCo 里全是**软约束**（弹簧-阻尼），每步求解器都要产生修正力把两个点拉在一起。
- **问题**：修正力高达 **40N（峰值 96~124N）**，且 10ms 内变化 17.8N → 落地时高频抖动 + 滑移放大器。

### joint 版（新，推荐）

```xml
<equality>
  <joint name="leg1_linkage_joint4" joint1="joint4" joint2="joint3"
      solref="0.0003 1.05" polycoef="-0.001650620535 -0.4535536832 -0.0502349092 0.01883377116 -0.03557780823"/>
  <!-- 共 8 个：4 腿 × 2 被动关节 -->
</equality>
```

- **原理**：用官方 `<joint>` equality 的四次多项式 `y−y0 = a0 + a1(x−x0) + a2(x−x0)² + a3(x−x0)³ + a4(x−x0)⁴`，让被动关节 y 跟踪曲柄 x 的运动学关系。**不需要约束力**，几何关系由多项式直接给定。
- **polycoef 顺序**：`a0 a1 a2 a3 a4`（升序），对应官方文档 `real(5)` 默认 `"0 1 0 0 0"`。**注意**：`np.polyfit` 返回降序 `[a4..a0]`，写入 XML 前要 `c[::-1]` 翻转。
- **solref=0.0003**（硬约束）：joint equality 也是软约束，但这里刚度只影响多项式跟踪的紧密度，不再有"缝合点被拉开 32mm"的物理后果，用硬值保证跟踪精度。
- **jont1/joint2**：`joint1`=被约束的被动关节（必填），`joint2`=驱动源曲柄（可选）。一个被动关节只能被一个 equality 引用（无冲突：8 个被动关节各对应 1 个 equality，曲柄 joint3/8/13/18 作为多个 equality 的只读输入是允许的）。

### 拟合精度（0~±120° 工作区）

| 腿 | 被动关节 | 拟合区 max 误差 | 零位误差 |
|----|---------|----------------|---------|
| leg1 | joint4 / joint5 | 0.093° / 0.255° | −0.095° / −0.195° |
| leg2 | joint9 / joint10 | 0.093° / 0.255° | +0.095° / +0.196° |
| leg3 | joint14 / joint15 | 0.125° / 0.394° | −0.113° / −0.036° |
| leg4 | joint19 / joint20 | 0.125° / 0.394° | +0.113° / +0.035° |

- 左右腿系数完美镜像（leg1↔leg2、leg3↔leg4），验证几何对称
- **已知局限**：四次多项式对曲柄摇杆机构在 ±120° 以外误差爆炸（几十度，死区）。拟合区限定 0~±120° 是权衡结果（leg1 试点已验证：全范围 0~170° 拟合零位偏 3~5°；限 120° 后拟合区 max<0.4°）。**步态曲柄角建议控制在 ±120° 内**。

## 5. 来龙去脉：落地抖动/滑移问题完整时间线

### 5.1 现象

机器人落地后持续抖动 + 向前滑移（10s 滑 2.5m），初看像"地面没摩擦"。

### 5.2 排查结论（7 项排除法）

| # | 假设 | 结果 |
|---|------|------|
| 1 | 地面没摩擦 | ✗ friction=1.0 正常 |
| 2 | 摩擦系数不够 | ✗ 提到 10 仍前倾，反证脚掌没真着地 |
| 3 | mesh 自碰撞卡腿 | ✗ 关碰撞直接穿地 |
| 4 | 膝关节塌陷 | ✗ 锁膝仍滑 |
| 5 | 地面高度不对 | ✗ 调 0 仍滑 |
| 6 | 前后腿不等长 | ✓ 站姿不平衡（诱因） |
| 7 | 四连杆约束修正 | ✓ 主因（放大器） |

### 5.3 根因（已定位，未修复）

**前后腿垂直长度差 43.2mm**（挂载点差 25mm + 腿骨差 18mm，geom 级测量）：

```
悬空零位后腿比前腿长 43.2mm
→ 四脚着地时身体前倾，pitch = asin(43.2/330) = 7.52°（实测 7.5° 完全吻合）
→ 重力沿脚掌平面分量 ≈ 1.7N，脚掌仅 10×10mm，静摩擦锥余量不足 → 缓慢持续滑移
→ 四连杆 connect 约束为维持闭合持续修正（40N 高频力）→ 放大抖动
```

**关键证据**：方案 E 查表版把 connect 删光后约束力 40N→0、滑移 203cm→9cm，**但 pitch 仍 +7.5°**——证明 connect 只是放大器，根因是 43.2mm 不等长。

### 5.4 方案演进（A→E）

| 方案 | 做法 | 结论 |
|------|------|------|
| A | 控制层弯后腿膝角补偿不等长 | ✗ 传动比 1:0.5 放大不足，预弯 40° 只降 pitch 2.2°；且扫错关节（joint2 而非 joint3），不可行 |
| B | 结构级调整挂载高度 | **推荐治本**：前腿挂载下移 25mm 或后腿上移，未做 |
| C | 加大脚掌接触面 | 后续迭代建议（真机也要做） |
| D | 调软 connect 约束 | ✗ 只是定位验证：弱约束后不抖不滑，但四连杆被拉开 32mm，步态精度崩 |
| E-v1 | 删 connect + 查表联动（position actuator 设被动角） | ✓ 约束力归零，但查表是"非官方做法"，且 actuator 额外 8 个增重负担 |
| **E-v2** | **删 connect + `<joint>` equality 四次多项式（官方）** | ✅ **最终方案**：leg1 试点用户验证"效果和 leg3 差不多"，扩展 4 腿 |

### 5.5 为什么最终选 joint equality（而非查表）

1. **官方做法**：MuJoCo 文档（XMLreference equality/joint）明确定义四次多项式跟踪，社区 BRUCE 指南也指出 connect 是权宜之计
2. **无额外 actuator**：查表版需要 8 个 position actuator（kp=100 伺服），joint equality 直接约束关节，不引入伺服动态
3. **物理干净**：无约束修正力（connect 的 40N）、无伺服抖振

### 5.6 遗留问题（下一阶段任务）

1. **【最重要】前后腿不等长 43.2mm 未修**：方案 B（改模型挂载点）或新方案，修完才能根治滑移
2. **拟合区 ±120° 限制**：步态设计需保证曲柄角不超限
3. **被动关节真实执行**：joint equality 让被动关节"自动跟对"，但真机上四连杆是机械耦合，需确认步态规划里的被动角假设一致
4. **mesh 自碰撞**：诊断报告提到 joint2/7/11/16 欠调 5~14° 根因是 base↔Link2 几何干涉，待 mesh 碰撞处理

## 6. 关键技术笔记（踩坑记录）

1. **多腿连续扫描状态污染（本次新发现）**：在同一 MjData 上连续扫描 4 条腿时，上一腿的残余 ctrl（如 leg1 停在 170°）会经 base_link 约束反力污染下一腿的扫描数据（leg2 边缘抖动 9.5°、拟合误差 3.58°）。**修复：每腿扫描前 `mj_resetData` + 清零全部 ctrl，只驱动目标腿曲柄。** 修复后 leg2 误差降到 0.255°，与 leg1 严格对称。
2. **单关节 actuator 的 `actuator_trnid[i,1]` 是 −1**（不是 0），找 ctrl 索引时要注意。
3. **纯运动学扫描**：无重力 + 无地面 + connect 硬约束（solref=0.0003），排除重力/接触/约束松弛污染，才能得到干净的四连杆几何关系。
4. **拟合范围取舍**：全范围 0~170° 拟合零位偏差 3~5°；限 0~120° 后拟合区 max 0.09~0.39°、零位 ~0.2°，但 120°+ 死区误差爆炸。这是多项式对曲柄摇杆机构的固有局限。
5. **不能分段拟合**：polycoef 固定 5 系数、无按输入范围切换机制；一个 joint 只能被一个 equality 引用 → 分段拟合在官方做法下不可行。
6. **脚高测量必须用 geom 级变换**（`d.geom_xmat/d.geom_xpos`），用 body 变换会漏 geom 偏移（曾把 43.2mm 误测成 30mm）。
7. **mujoco 3.11 无 `eq_polycoef` 属性**，polycoef 存于 `m.eq_data[e, :5]`。
8. **`np.polyfit` 降序 vs XML 升序**：polycoef 写入前必须 `c[::-1]`。
9. **左腿查表 0° 边界外插**：`np.interp(0, [-172..-0.01], ...)` 会返回末值 +190° 撞限位 → 用右腿表镜像（查 −q3 取反）规避（查表版遗留，joint 版无此问题）。
