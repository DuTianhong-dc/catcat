## 2. 状态空间的嵌套结构（Table I 原文）

```
Self-Righting : gravity, joint pos/vel, history of joint position errors & velocities,
                actuator model, desired joint position, previous action
Standing Up   : Self-Righting 状态空间 + base linear velocity in body frame (v_B_IB)
Locomotion    : Standing Up 状态空间 + velocity commands + estimated base height (he)
Height Estimator (真机): 用 gravity/joint/误差史 回归 base height
```

→ **`c_h` 作为成本项用仿真真值即可，不需要把 height 放进网络观测**；
这与"真机靠 height estimator 估高"不冲突，是训练/部署的分工。

## 3. 高度项 vs 高度判据（上一轮结论的正确边界）

2026-11-05 上午实测证明：**二值高度分类判据不可用**（站姿与趴姿在默认伺服下
沉降到同一个 z=0.1473；侧躺/四脚朝天只差 3.8 mm；绕 y 侧躺反而比站姿高 86 mm）。
固件 `cat_recover.c` 因此删掉 `is_standing` 的高度判据、改用 `gz` 持续达标。

但本任务的 `c_h` 是**连续成本项**：
- 目标明确（站姿高度 0.1473），不存在"分类姿态"的歧义；
- 用仿真里可直接读到的 `qpos[2] − floor_z`，不进网络输入；
- 只罚「低于目标」的单边平方，站过头不罚（避免与 `c_jp`/`c_o` 掐架）。

所以两者不矛盾：**弃用的是阈值分类，保留的是连续梯度**。论文自己也是这么分工的
（self-righting 无 height cost，standing-up 才加 `khch`）。写论文时不要把这两件事混写。

## 5. 验收判据（`scripts/_eval_standup.py` 草案）

16 回合 × 250 步，策略 vs 零动作基线（`delta_current` 下 a=0 = 保持当前角）：

| 指标 | 合格线 |
|---|---|
| 末 50 步（1 s）`up_z` 均值 | **> 0.9**（正立） |
| 末 50 步基座高度 | **> 0.13 m**（站起来；站姿 0.1473） |
| 末态 `‖q − q_stand‖` | 显著小于零动作基线 |
| 站起时间 | 首次同时满足上两条，越短越好 |
| 回合回报 | 与训练日志最后一次 eval 同量级（确认权重/归一化接对） |
| `c_height` 均值 | 应随训练下降 |

**必须显著优于零动作基线** —— EXP-01 的 P0 预实验就是栽在"策略只比基线好一点点"
（25% vs 19%），不能只看奖励上涨。

## 6. 风险与待办（未验证，不能写成结论）

| # | 项 | 说明 |
|---|---|---|
| 1 | **保持力矩** | 趴姿腿几乎水平、力臂最大；7.4 V STS3215 是否堵转未算，真机部署前必须校核 |
