## 4b. 第 0 步物理基线（2026-11-24 新增）

不跑 RL，只对 300 条起点下发恒定目标，比较两种动作参数化：

| 分组 | 起始 bz | anchor（目标恒为站姿） | delta（`a≡0` 的 delta_current） |
|---|---|---|---|
| near_stand | 0.145 | **0.143 / up_z +0.93 / τ 0.35 N·m** | **0.074 / up_z +0.70 / τ 0.05 N·m** |
| transition | 0.120 | 0.102 / +0.31 | 0.069 / +0.55 |
| original | 0.092 | 0.087 / +0.05 | 0.073 / +0.11 |
| 站住率 | — | **117/300 = 39%** | **0/300 = 0%** |

结论：**`delta_current` 在 `a=0` 时确实没有抗重力力矩，8 s 内塌 7.1 cm；换成绝对锚点则稳站且力矩富余 87%。**
执行器、`kp/kv`、`τ_max` 都不是瓶颈，也不需要靠"零阻尼震荡"来解释。详见 `logs/README.md`。

## 0. 一句话现状

四足机器猫的「起身站立」策略已经能
（a）从**已经接近站姿**的起点站住约 1–3 秒（最好一条连续 2.9 s），
（b）从**趴姿**基本起不来（22 条趴姿起点里 21 条最长站稳 0 拍），
（c）站上去时姿态很怪（三足支撑、一条腿翘起，关节角离站姿 30–60°），
并且**任何一轮训练都无法把机身高度维持在起始高度之上**（高度曲线全程单调下沉）。

## 1. 背景：三个网络的分工

硬件是自制四足机器猫（12 自由度，腿是五连杆，膝部空间单自由度），仿真用 MuJoCo + MJX（JAX），
真实部署走 SIL 桥接。控制频率 50 Hz（`dt=0.02`，每个控制拍内物理子步 `nsub=10` → 物理 500 Hz）。

| 网络 | 代号 | 任务 | 当前状态 |
|---|---|---|---|
| 第一 | p1 | 从**倒置**（四脚朝天）翻身到 `up_z≈0.5`（侧躺/半起） | 已可用，50/50 成功率，真实落点分布 `up_z 0.45–0.52` |
| **第二** | **s2stand** | **从各种倒地/蹲姿起身并站稳**（本文主角） | 卡住：见 §5 |
| 第三 | walk | 行走（指令跟踪） | 已可用，能在平地站立/行走 |

观测（第二网络，共 9 个块拼接）：机体系重力向量、陀螺、12 关节角、12 关节角速度×0.05、
关节角误差、最近 1/2/3 拍动作、上一拍电机目标。指令固定为 0（不做速度跟踪）。
动作：12 维，**`delta_current` 参数化**：

```
m_t = clamp(q_t + 0.25 * a_t, 关节限位)      # m_t = 电机目标角，q_t = 当前关节角
a_t ~ N(μ_θ(obs), σ²)，训练时采样，验收时用 μ（确定性）
```

终止条件（v13 起）：`stand_fall` 锁存式 —— **本回合曾经** `up_z>0.85 且 bz>0.10`（站正过）之
后再掉到 `up_z<0.65` 或 `bz<0.06` 立即结束。回合上限 250 拍（5 s）。

## 3. 「站住」的验收口径（讨论方案前必须先对齐）

两条判据，都在同一起点库上跑闭环、确定性策略、DR=train 口径：

**A. `physical_stand`（严）**：连续 25 拍（0.5 s）满足
`up_z>0.95` 且 `bz>0.115` 且 `≥3 只足与地面真实接触` 且 `机身不触地` 且 `|ω_xyz|<0.5`。

**B. 双指标（松，用户更认这个）**：连续 10 拍满足
`bz>0.115` 且 `up_z>0.95` 且 `max|q − q_stand|<0.25 rad`（`q_stand` 全 0）。

附加诊断量：接触期足端滑移（mm/拍）、四足投影四边形面积（×Aref）、质心到多边形内距（mm）、
「翘腿占比」= 站立相里恰好 3 足着地的拍数占比。

## 4. 奖励系统的完整机制（第二网络）

框架是 MuJoCo Playground 风格：每个 term 返回未加权量，乘 `scales[k]`，求和后乘 `dt`，
再 `if cost_mode: total = -total`，最后 `reward = clip(total + shaping + bonus, clip_min, 10000)`。

**v13/v14 的配方**：`cost_mode=True`（成本取负 → 正奖励）、`clip_min=0`（每拍奖励非负）、
13 个 term、`stand_fall` 终止、**没有** `c_fall`。

### 4.1 各 term 的公式（v14 实际生效）

| term | 含义 | 公式要点 | v14 尺度 |
|---|---|---|---|
| `c_orientation` | 姿态 | logistic 核，按起点基线归一 | 6.0 |
| `c_joint_pos` | 目标关节角 | `Σ_j K(e_j) − K(0)`，logistic 核 `alpha=1.5`，e=关节误差 | **8.0** |
| `c_joint_accel` | 关节加速度 | `Σ qacc²` | 0.0005 |
| `c_action_diff` | 动作变化 | `Σ(a_t − a_{t−1})²` | 0.0005 |

### 4.2 三道门控（tricks，也是病灶）

1. **姿态门控 `c_jp_gate_mode="stab"`**：`c_joint_pos *= (1 − _stab_raw)`，`_stab_raw` 由支撑几何算，
   0=稳、1=不稳。语义是"站不稳时先别管姿态"。
2. **高度资格 `w_h`**：`c_stab`、`c_area` 都乘 `clip((bz−0.075)/(0.1473−0.075),0,1)` —— 高度是"放大器"不是"目标"。
3. **接触门控（v14 新增）**：`c_area/c_stab` 只用**着地足**构成多边形（非着地足的投影搬到着地足上，
   重复顶点 shoelace 贡献 0）；接触数 <3 时两项置 0；三足时参考面积取 `Aref×0.5`。

## 6. 已确认的机制性结论（附证据，这些不必再验证）

**6.1 策略的失败是"主动选择摊开趴平"，不是随机摔倒。**
三组起点、四个版本一致：面积涨到 1.6–2.6×Aref、机身压到 0.05–0.09、`up_z` 保持 0.99（不歪）。

**6.2 面积/稳定奖励"不看接触"是主要漏洞（已在 v14 修）。**
原实现把四足 site 投影不论是否着地都计入 → 抬一条腿把投影外推，面积与质心内距同时变大，
`c_area+c_stab`（占毛额 67–78%）都加钱 → 稳定收敛到"三足支撑、一腿翘起"。
v14 改成只用着地足构成多边形后，站立相 ≥3 足接触从 47% 升到 64%，**但"翘腿"仍占 14–23%** ——
因为三足时参考面积取 `Aref×0.5`，**三条腿摆得好同样拿满分**，只是不再有额外奖励。

**6.3 `c_joint_pos` 在起作用，但"罚得多、梯度小"。**
它是第二大项（+165/回合，28%）。瓶颈是 logistic 核（`alpha=1.5`）在 0.4–1.2 rad 区间接近平顶：
末态关节误差 1.02 rad、全程最小值也有 0.47 rad —— 策略选择"交罚款"而不是把腿摆正。

**6.4 高度没有任何正收益。**
`c_height` 权重 0；`c_height_delta` 只是一次性棘轮；`c_stab/c_area` 把高度当"资格系数"（0.075→0.1473 线性）。
所以"跌得慢 + 跌的过程里把支撑几何摆好"就能拿大部分分，**站起来本身不产生边际收益**。

**6.5 `delta_current` 在重力下有积分漂移。**
零动作时目标角跟随当前角：腿被压弯 → 目标角下移 → 正反馈塌缩。这解释了"高度平滑漏气 + up_z 保持 1"的签名，
也解释了为何"什么都不做"反而稳。`walk` 网络用的是 `q_stand + a·scale`（绝对锚点），没有这个问题。

**6.6 探索方差由 `entropy_cost` 决定，`init_noise_std` 无效。**
导出脚本原先把头层后 12 个参数当 `log_std`，实际是 `scale = softplus(p)+0.001`。
实测 p≈0 → **σ≈0.69**（p1/v11/v12/v13/v14 五条策略完全一致）；
`init_noise_std=0.35` 只把初值设到 σ≈0.30，训练中被熵项推回 0.69。
含义：`tanh` **之前**的采样尺度是 0.69（**不是实测目标角抖动**）；经 tanh 与 ×0.25 之后，
实际每拍目标角抖动上限约 0.17 rad，真实抖动需实测。与之对照的是站姿四边形半宽 62 mm。

**6.7 "非负奖励 + 提前终止"只解决了"止损套利"，没解决"躺平收益"。**
walk 的口径是 `cost_mode=False` + `clip_min=0`（`termination=−200` 被 clip 抹平）；
s2 的 v13/v14 同构（`cost_mode=True` + `clip_min=0`，删 `c_fall`）。
但 s2 的正项在"趴着"时几乎为零 —— 于是"0 分"与"站起来但没站好"不可区分，**梯度在整段消失**。

**6.8 阶段 2（站正）在实机上几乎不可达，但跳级无害。**
阶段判定 `≥3足 → +up_z≥0.95 → +bz≥0.115` 里，`up_z` 与 `bz` 高度共线：站正即站高，
实测阶段 2 只占 0.2% 拍（140/6000）；趴着虽 `up_z=0.99` 但不足 3 足，落在阶段 0。

## 7. v15 的「阶段式全奖励」及其失败原因（最新一轮）

设计：7 项**有界奖励** `r∈[0,1]`，无负项；四个阶段累积判定（前一级是后一级的门控）；
每项权重随阶段变化（小/中/大/最大 = 0.25/0.5/0.75/1.0）。

| 项 | 公式 | 阶段1→4 权重 | 备注 |
|---|---|---|---|
| `r_pose` | `1 − clip(qerr/1.0,0,1)` | 0.25·0.25·0.50·1.00 | |
| `r_stab` | `clip(m / 0.0754, 0, 1)` | 1.00·0.50·0.25·0.25 | 上界 = 站姿内距 62.8 mm × 1.2 |
| `r_area` | `1 − clip(\|A/Aref−1\|/0.6, 0, 1)` | 1.00·0.50·0.25·0.25 | 双侧、有界 |
| `r_hdelta` | `clip(Δbz/0.01, 0, 1)` | 0.25·0.50·1.00·0.25 | 非棘轮，两拍差 |
| `r_upz` | `clip((up_z−0.6)/0.4, 0, 1)` | 0.25·1.00·0.50·0.25 | 新加的"站正"项 |
| `r_contact` | `1 if ≥3 足 else 0` | 全程 1 | |
| `r_slip` | `1 − clip(v_foot/0.02, 0, 1)` | 全程 1 | 用足端速度，非接触滑移 |
| 阶段基础分 | 0 / 0 / 0.6 / 2.0 / 3.0（含未站档） | | 保证逐级递增 |

**另加"未站档"**（索引 0）：`pose=stab=area=0`，`hdelta=0.25`、`upz=0.25`、`contact=1`、`slip=1`。
理由是"未站"若 0 分，趴着就没有梯度。

**结果：退化。** v15@327k 物理 7.8%、v15@655k **0%**；面积涨到 1.8–2.1×；两足着地 87–90%；5 s 末高度 0.052。

**失败原因（诊断，置信度高）**：未站档的 `r_slip`（不动即满，0.9 分）+ `r_upz`（趴着也 `up_z≈1.0`，0.5 分）
= **"躺平不动" 1.4 分/拍**的稳定盆地；而站着（阶段 3）虽然值 5.9 分/拍，但在 σ=0.69 的噪声下早期风险高。
策略 30 万步内就掉进盆地并越躺越平。
根子还是 6.4 + 6.6：**up_z 区分不了"趴平"与"站直"，而"静止"被当成好事**。

结合 v13–v15 的高度曲线、v14 奖励账本和 v15 的退化现象，可以比较明确地判断：**策略不是"学不会"，而是被当前控制接口、终止条件和奖励盆地联手推向了"躺平最优解"。**

### 一、从日志与脚本反推的 4 个核心病根

1. **`delta_current` + `kv=0` + 高探索噪声造成"重理单向下沉棘轮"（最核心）**
   当前动作映射为 m_t = clamp(q_t + 0.25 a_t)，且关节 PD kv=0。这意味着策略输出 a_t=0 时，PD 目标角等于当前角，**稳态抗重力力矩为 0**。
   要撑住 1.959 kg 机身，网络每一拍都必须精准输出非零偏置来抵消重力；而当前稳态探索方差 σ≈0.69（每拍 ±0.17 rad 抖动），只要某一拍少给了一点，重力把腿压弯后 q_{t+1} 下移，下一拍基准点跟着下移，形成正反馈塌缩。
   这直接解释了 v14 近站组高度从 0.145 m 单调掉到 0.091 m、三代 checkpoint 全程峰值从未举过起点高度的现象。相比之下，walk 用绝对锚点 q_stand + a_t·scale，零动作天然产生回弹抗重力力矩，稳定得多。

2. **`stand_fall` 锁存终止 + 纯正奖励，反向惩罚了"尝试起身"（交接文档里容易忽略的隐蔽坑）**
   在纯正奖励（clip_min=0）且 γ=0.9988 的设置下，**活满 250 拍就是最大收益**。
   当前 `stand_fall` 的逻辑是：曾满足 up_z>0.85 且 bz>0.10 后再跌落才提前终止。结果变成：**一直趴在 0.05–0.08 m 永远不触发锁存，稳活 250 拍白嫖未站档分数；一旦尝试抬身冲过 0.10 m 站不稳，就会提前终止，丢掉后面 200 拍的全部奖励。**
   这正是 v15 的 eval 奖励涨到 15.86、回合步数涨到 237，而 655k 物理达标率反而归零、末态高度跌到 0.052 m 的直接推手。

3. **奖励函数制造了高薪"躺平盆地"且缺少持续高度梯度**
   v14：c_height=0，c_height_delta 是一次性棘轮；占总奖励 59% 的 c_stab 从 0.075 m 就开始给分，加上 c_joint_pos 的 logistic 核在 0.4–1.2 rad 饱和平顶、三足参考面积按 0.5×Aref 计算，策略"压低叉腿/翘单腿"性价比远高于站直。
   v15：未站档中 r_slip（脚不动就拿满正分）叠加 r_upz（趴平也 up_z≈1.0）形成稳定盆地，加上 5 档阶梯门控在未达标前梯度断层，策略直接锁死在两足/机身躺平。

4. **训练样本极度稀疏（1M 步摊给 300 条异构起点）**
   总步数 983,040、单回合 250 步，总共只跑了约 3,932 个回合，平摊到 300 条跨度极大（近站/过渡/趴/侧/仰）的起点，每条起点平均只采样 ~13 次。在无足端接触感知（ablate_contact=true）和无力矩感知（ablate_tau=true）下，不同起点的梯度互相拉扯，很难在 1M 步内同时收敛。

## 2. 状态空间的嵌套结构（Table I 原文）

```
Self-Righting : gravity, joint pos/vel, history of joint position errors & velocities,
                actuator model, desired joint position, previous action
Standing Up   : Self-Righting 状态空间 + base linear velocity in body frame (v_B_IB)
Locomotion    : Standing Up 状态空间 + velocity commands + estimated base height (he)
Height Estimator (真机): 用 gravity/joint/误差史 回归 base height
```

→ **`c_h` 作为成本项用仿真真值即可，不需要把 height 放进网络观测**；
这与"真机靠 height estimator 估高"不冲突，是训练/部署的分工。

## 3. 高度项 vs 高度判据（上一轮结论的正确边界）

2026-11-05 上午实测证明：**二值高度分类判据不可用**（站姿与趴姿在默认伺服下
沉降到同一个 z=0.1473；侧躺/四脚朝天只差 3.8 mm；绕 y 侧躺反而比站姿高 86 mm）。
固件 `cat_recover.c` 因此删掉 `is_standing` 的高度判据、改用 `gz` 持续达标。

但本任务的 `c_h` 是**连续成本项**：
- 目标明确（站姿高度 0.1473），不存在"分类姿态"的歧义；
- 用仿真里可直接读到的 `qpos[2] − floor_z`，不进网络输入；
- 只罚「低于目标」的单边平方，站过头不罚（避免与 `c_jp`/`c_o` 掐架）。

所以两者不矛盾：**弃用的是阈值分类，保留的是连续梯度**。论文自己也是这么分工的
（self-righting 无 height cost，standing-up 才加 `khch`）。写论文时不要把这两件事混写。

# 第 0 步 物理基线：纯 PD 能不能撑住

> 2026-11-24 18:5x 用 `../scripts/pd_baseline.py` 跑的，纯 CPU、无 RL、无训练。
> 目的是回答外部诊断的第一条假设：**"delta_current + a=0 → 稳态抗重力力矩为 0 → 重力单向下沉棘轮"**。
> **结论：这条成立，而且差得很远**——同一批起点，只换参数化，站住率从 39% 变成 0%。

## 设置

- 模型 `model/scene_selfright_full_v2.xml`；`kp=15.85/15.85/57.22`、`kv=0.56/0.56/2.02`（`dof_damping`，不是 0）、`τ_max=2.73/2.73/5.19 N·m`
- 起点库 `data/curriculum_mix.npz` 全部 **300 条**（near_stand 60 / transition 180 / original 60）
- 每拍重写 ctrl，50 Hz × 8 s，物理 500 Hz（每拍 10 子步）
- 两种模式：
  - **anchor**：`ctrl = q_stand = 0`（绝对锚点参数化）
  - **delta**：`ctrl = 当前关节角`（`delta_current` 下 `a≡0` 的等价物）

| **站住率（bz>0.12 且 up_z>0.8）** | 300 | — | **117/300 = 39%** | **0/300 = 0%** |

| 模式 | τ p95 | 顶满 τ_max 比例 | 末段关节角速度 |
|---|---|---|---|
| anchor | 0.26–0.35 N·m（10–13%） | 0.6–0.9% | 0.00 rad/s |
| delta | 0.02–0.05 N·m（≈1%） | 0.0% | 0.01 rad/s |

## 三点判读

1. **delta 的 a≡0 确实没有任何抗重力力矩**：near_stand 组 8 s 内从 0.145 掉到 0.074（−7.1 cm），
   全程力矩只有 0.05 N·m，等于自由下沉。→ 外部诊断第 1 条被物理仿真直接证实。
2. **anchor 能稳稳撑住，而且力矩富余 87%**：0.143 m（只掉 2 mm）、up_z 0.93、0.35 N·m。
   → 执行器、`kp/kv`、`τ_max` 都不是瓶颈；"站不住"不是物理能力问题。
3. **不震荡**：两种模式末段角速度都 ≈0。`kv` 实际是 0.56/2.02（我最初看错的 0.01 是取错了索引），
   阻尼够用 → 外部诊断里"零阻尼剧烈震荡"这一条不成立。

def feet_down(m, d, thr=0.005):
    z = [float(d.site_xpos[mujoco.mj_name2id(m, mujoco.mjtObj.mjOBJ_SITE, n)][2]) for n in FEET]
    return sum(1 for v in z if v < thr), z


def run_one(m, q0, nstep, vadr, jadr_now, ctrl_q, foot_ids, delta=False):
    d = mujoco.MjData(m)
    d.qpos[:] = q0
    d.qvel[:] = 0.0
    d.ctrl[:] = 0.0
    mujoco.mj_forward(m, d)
    bz, upz, tau, qv, nfeet = [], [], [], [], []
    for k in range(nstep):
        d.ctrl[0] = 0.0
        if delta:                       # a≡0 的 delta_current：目标角 = 当前角（无重力补偿）
            d.ctrl[1:13] = np.asarray(d.qpos)[jadr_now]

            d.ctrl[1:13] = ctrl_q
        for _ in range(NSUB):
            mujoco.mj_step(m, d)
        qp = np.asarray(d.qpos)
        bz.append(float(qp[2]))

        tau.append(np.abs(np.asarray(d.actuator_force)[1:13]).copy())
        qv.append(np.abs(np.asarray(d.qvel)[vadr]).copy())
        nfeet.append(sum(1 for s in foot_ids if d.site_xpos[s][2] < 0.005))

## 五、机械回差（2026-10-28，结构照抄 Open Duck）

结构：**同一个 body 内两个串联 joint**（与 `open_duck_mini_v2_backlash.xml` 一致）

```
<body LinkN>
  <joint jointX/>        ← 主动
  <joint jointX_bl/>     ← 被动间隙 ±0.09°，同 body 同轴（MuJoCo 自动串联）
  <inertial .../>        ← 质量不用搬，天然在间隙之后
  ...geom / 子 body...
</body>
```

**为什么不插一层 `_bl` body**：MuJoCo 的 body 可以挂多个 joint，按出现顺序串联。插 body 就得额外把 `inertial` 搬到子 body，否则重力矩不经过间隙（实测膝的 4 个回差角恒为 0）；搬 inertial 又会让本脚本的惯性主轴校验（κ 检查）失效。同 body 双 joint 两件事都不用做。

### 两个关键判断

**① kp 和 τ_max 改不改都一样** —— 训练时的域随机化本来就覆盖它们：

| 参数 | DR 范围 | 实测值位置 |

| kp | 17.11 × [0.8, 1.2] = 13.7 ~ 20.5 | 15.85，**落在中间** |

也就是说策略训练时见过这些值，不存在分布外。反过来说，**Open Duck 那份 BAM 参数在同款舵机上确实通用**，个体与电压差异只造成 7~15% 偏差。

**② 唯一量级错误的是速度上限**，见第八节。

### 膝为什么要 ×i²

舵机位置环作用在舵机角 θ 上（θ − θ₀ = i·(q − q₀)），力矩传到关节端再乘一次 i：

```
τ_joint = i · kp_srv · i · (q_cmd − q) = (kp_srv · i²) · Δq
```

同理 forcerange ×i、damping/armature ×i²、frictionloss ×i。**×i 折算这一层是我们独有的**：Open Duck 的腿是直驱（i = 1），我们是五连杆。

### 传动比取 1.90（不是零位值，也不是下限）

i 在行走区的变化：

| κ 绝对 | −55° | −70° | −77.7°（零位） | −80° | −90° |
|---|---|---|---|---|---|
| i = dq₃/dκ | 1.78 | **1.69**（最小） | 1.78 | 1.82 | 2.09 |

- 取**零位 1.7787**：那是局部最小值，深折叠时会明显偏软；
- 取**下限 1.69**：会让零位附近的关节刚度和速度被过度软化 12%，而那里正是摆动最快的地方；
- 取 **RMS 1.90**：全行走区的相对误差对称分布（±11%），且在 DR ±20% 覆盖内。

历史注记：原值整包抄自 `open_duck_mini_v2_backlash.xml` 内嵌的 `sts3215` class。注意 `joints_properties.xml` 是**死文件**（2025-03-20 起不再更新也不再被 include），不要照它抄（那是 17.8 / 3.35 / 0.60 / 0.052 / 0.028 的旧值）。另外 `open_duck_mini_v2.xml`（无回差主模型）用 kp=13.37，与我们结构不同，未采用。

**地面：friction 0.6 + `priority="1"`**（对齐 `scene_flat_terrain.xml`，condim=3 也一致）。

`priority="1"` 是关键：MuJoCo 里 **priority 高的 geom 独占决定接触参数**（friction/condim/solref/solimp），不取 max。没有它时接触摩擦 = `max(0.6, 脚球默认 1.0)` = **1.0**，比他们的 0.6 粘 67%。加上后实测接触摩擦 = **0.6**。

| 膝（i = 1.90） | 4.9 / 1.90 = **2.58 rad/s** | 5.24（统一标量） | **2.58** |
| 位置跟随一阶惯性 | **60~90 ms**（3~4 拍 @50 Hz） | `action_delay` 恒 0 | **0~2 拍**（近似） |

**原来的 5.24 rad/s 抄自 Open Duck，而那是直驱（i = 1）**。我们膝上有五连杆，同一个数直接用在膝上等于**快了约 2 倍**——策略会输出真机根本执行不了的摆腿指令，表现为真机上摆腿跟不上、步态走形。

⚠️ 所以速度上限必须**逐关节**：髋 4.9、膝 2.58。训练侧 `c.max_motor_velocity = (4.9, 4.9, 2.58) * 4`（顺序 = `ACTIVE_JOINTS`），固件 `OBS_MAX_VEL[12]` 必须逐项对齐，两处任何一处写错都会让 sim 与真机分叉。

**关于带宽**：小信号（±2°）扫频给出 **~3 Hz** 带宽，说明位置环本身不慢；大信号在 2 Hz 就衰减到幅值比 0.35，是**速度饱和**而不是带宽不足（±10° @ 2 Hz 需要 2.2 rad/s 峰值速度）。所以训练里用"逐关节限速"建模是正确的主线，**暂时不需要额外加一阶低通**。

## 十一、MuJoCo Live 自包含包（2026-11-15）

`live.mujoco.org` 是浏览器 WASM，**拖单个 `.xml` 只会把那一个文件读进内存 VFS**，
`meshes/*.STL` 等相对路径资源不会跟着进去，因此报 `could not open mesh`。
官方要求拖「standalone .xml」或「self-contained .mjz / .zip」。

| 产物 / 脚本 | 用途 |
|---|---|
| `cat4.0_live.mjz` | 可直接拖进 MuJoCo Live 的自包含包（7.64 MB / 30 条目） |
| `tools/make_mjz.py` | 重新打包：自动沿 `include` / `file` 属性递归收集依赖，解压后编译自检 |

```bash
cd models/cat4.0 && python tools/make_mjz.py
```

包内结构（MJZ = zip，根目录 `model.xml` 是 4.0 root XML discovery 的第 1 优先级）：

```
cat4.0_live.mjz
├── model.xml              ← scene.xml 的内容（带地面/灯光/stand keyframe）
├── robot.xml              ← model.xml include 了它，必须同包
├── meshes/*.STL           ← 27 个，大小写与 XML 引用严格一致（WASM VFS 大小写敏感）
└── textures/desert.png
```

- 入口用 **scene.xml** 而不是 robot.xml：后者没有地面和灯光，打开会看到机器猫自由落体。
- `model.xml` 是 `scene.xml` 的副本，内容不改，`include`/`file` 相对路径保持原样。
- ⚠️ 本机 MuJoCo 是 **3.12.0**，不认 `.mjz`（4.0 新增格式）；打包脚本的编译自检是
  **解压后按 `model.xml` 编译**，验证的是包自洽，不等于 4.0 WASM 实测通过。
  4.0 破坏性变更（cable/composite/flex 移除、RK4 语义、重复 include 报错等）
  已逐条核过 `*.xml`：本模型用 `implicitfast`、无 tendon/sidesite、只 include 一次，不受影响。
- 别用 `.mjb` 绕：MJB 版本绑定，3.12 编出来的 4.0 加载不了。
